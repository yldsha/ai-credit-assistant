# Умный кредитный кабинет предпринимателя

**Хакатон «Альфа-Будущее» · кейс Альфа-Банка · команда Cash Flow Crew**

**Демо-видео:** https://drive.google.com/file/d/1D5OcEXZz2l2vTd689ZMrbORi8Rx72KWr/view?usp=sharing

**Быстрый старт:** `docker compose up --build` → http://localhost:5173

Цифровой сервис для автоматизации кредитования малого и среднего бизнеса. Проект объединяет подбор кредитных продуктов, оформление заявки, проверку данных, ML-скоринг и принятие кредитного решения в едином процессе.

## 1. О проекте

Предприниматели сталкиваются со сложностью выбора финансирования, необходимостью заполнения большого количества данных и недостаточной прозрачностью рассмотрения кредитных заявок.

Наше решение направлено на упрощение кредитного процесса за счёт автоматизации стандартных операций и использования машинного обучения для оценки кредитного риска.

**Основные возможности:**

- Подбор кредитных продуктов по параметрам бизнеса.
- Создание и отправка кредитных заявок.
- Проверка сведений о компании через имитаторы ЕГРЮЛ, ФНС и БКИ.
- Расчёт вероятности дефолта с помощью ML-модели.
- Автоматическое принятие кредитных решений.
- Передача нестандартных заявок сотруднику банка.
- Формирование альтернативных кредитных предложений.
- Отображение статусов и истории рассмотрения.

## 2. Как работает система

Кредитный процесс состоит из нескольких этапов:

1. **Выбор финансирования.** Клиент определяет цель, сумму и срок кредита.
2. **Создание заявки.** Предприниматель предоставляет сведения о компании и финансовом состоянии.
3. **Проверка данных.** Система обращается к моделируемым источникам ЕГРЮЛ, ФНС и БКИ.
4. **Скоринговая оценка.** ML-модель рассчитывает вероятность дефолта (PD).
5. **Принятие решения.** Decision Engine применяет кредитные правила.
6. **Получение результата.** Клиент получает решение, а при необходимости заявка направляется сотруднику.

### Возможные кредитные решения

| Решение | Описание |
|---|---|
| `approved` | Автоматическое одобрение |
| `rejected` | Отказ |
| `manual_review` | Ручное рассмотрение |
| `need_info` | Запрос дополнительных данных |
| `counter_offer` | Альтернативное предложение |

Путь заявки: `draft → submitted → checking → scoring → решение`. После одобрения: `offer_accepted → contract_signed → disbursed`. Каждый переход сохраняется в истории; схема статусов — в [docs/credit_process.md](docs/credit_process.md).

## 3. Кредитная политика MVP

Для демонстрационной версии используются следующие правила:

| Параметр | Значение |
|---|---|
| Автоматическое одобрение | PD ≤ 5% при соблюдении остальных условий |
| Ручное рассмотрение по PD | 5% < PD < 15% |
| Автоматический отказ | PD ≥ 15% |
| Ручное рассмотрение по сумме | Предложение свыше 3 млн ₽ |
| Максимальная платёжная нагрузка | 50% |
| Критическая просрочка | Более 90 дней |
| Платёж больше 50% месячной выручки | Предложение меньшей суммы (`counter_offer`) |
| Мягкие сигналы риска (налоговый долг, просрочка 30–90 дней, более 5 запросов в БКИ) | Ручное рассмотрение |

Дополнительно учитываются регистрационный статус компании, наличие налоговой задолженности и другие факторы риска.

При превышении допустимой платёжной нагрузки система может предложить уменьшенную сумму кредита.

Пороги хранятся в `scoring/decision/config.json` и меняются без изменения кода. Это параметры демонстрационной политики, а не нормативы Альфа-Банка; обоснование выбора — в [анализе порогов PD](docs/pd_threshold_analysis.md).

## 7. Подбор продуктов

Каталог — 6 продуктов Альфа-Банка для бизнеса: кредит без залога, кредит с залогом, «Деньги на дело», возобновляемая кредитная линия, овердрафт, автокредит. Правила допуска (сумма, срок, возраст бизнеса, залог) восстановлены по калькулятору банка, платежи сверены с ним до рубля.

1. **Правила допуска** отсекают продукты, на которые клиент не проходит.
2. **Логистическая регрессия** (обучена на 20 000 синтетических заявок с разметкой по экспертным правилам) ранжирует подходящие продукты по цели и параметрам. Лучший по правилам продукт попадает на первое место в 84,7% случаев и в тройку — в 99,7%.
3. Клиент получает до трёх вариантов с метками «Лучший вариант / Тоже подходит / Альтернатива», причинами и ежемесячным платежом. Если ничего не подошло — подсказку, что изменить (например, добавить залог).

## 8. Скоринговая модель

Для оценки кредитного риска используется модель CatBoost.

Она использует 15 характеристик заявки и 4 производных показателя (долговая нагрузка, доля расходов, отношение кредита к выручке, покрытие залогом), включая:

- Сумму и срок кредита.
- Цель финансирования.
- Возраст и отрасль бизнеса.
- Годовую выручку.
- Ежемесячные обороты и расходы.
- Действующие долговые обязательства.
- Кредитные просрочки.
- Наличие и стоимость залога.

Модель формирует прогноз вероятности дефолта на горизонте 12 месяцев.

Качество на отложенной выборке: **ROC-AUC 0,79, Gini 0,58**. Модель откалибрована: средний PD на датасете совпадает с фактической долей дефолтов (7%). Для каждой заявки сотрудник видит топ-5 факторов (SHAP) с направлением влияния.

Для пяти демо-клиентов (сценарии 1–5) PD зафиксирован, чтобы сценарии воспроизводились одинаково. Для всех остальных заявок, включая сценарии 8–10, PD рассчитывает модель в реальном времени.

### Проверка через Swagger

1. Откройте `http://localhost:8000/docs`.
2. Выполните `POST /applications/draft` с тестовыми данными.
3. Сохраните полученный идентификатор заявки.
4. Выполните `POST /applications/{application_id}/submit`.
5. После завершения фоновой обработки откройте `GET /employee/applications/{application_id}`.
6. Сравните фактический статус с ожидаемым.

## 11. Ограничения MVP

Текущая версия является демонстрационным прототипом и имеет следующие ограничения:

- Используются синтетические данные.
- Внешние источники имитируются локальными API.
- Реальная выдача кредитов не выполняется.
- Аутентификация упрощена: роль выбирается на главной странице.
- Применяется локальная база данных SQLite.
- Пороги кредитной политики требуют статистической проверки.

Для дальнейшего развития предусмотрены улучшение интеграций, повышение безопасности, контроль SLA, расширение продуктовой аналитики и оптимизация скоринговых правил.
