# SLA обработки кредитных заявок

## Умный кредитный кабинет предпринимателя


## 1. Цель SLA

SLA (Service Level Agreement) — соглашение об уровне обслуживания, устанавливающее нормативные сроки выполнения операций.

В рамках кредитного кабинета SLA необходим для контроля скорости рассмотрения заявок, выявления задержек и повышения качества обслуживания предпринимателей.

Основные задачи:

- Сокращение времени принятия кредитного решения.
- Контроль сроков автоматической и ручной обработки.
- Выявление этапов, на которых возникают задержки.
- Повышение прозрачности кредитного процесса.

## 2. Нормативы обработки заявок

| Этап | Целевой срок | Ответственный |
|---|---|---|
| Регистрация заявки | До 5 секунд | Система |
| Автоматическое рассмотрение | До 2 минут | Система |
| Передача на ручную проверку | До 1 минуты | Система |
| Ручное рассмотрение | До 1 рабочего дня | Сотрудник |
| Отображение решения | До 5 секунд | Система |

Указанные сроки являются предлагаемыми нормативами MVP.

## 3. Правила расчёта SLA

Для каждого этапа фиксируются время начала и время завершения.

**Время обработки = Время завершения − Время начала.**

Правила отсчёта:

- Для автоматического решения — от отправки заявки (`submitted`) до получения итогового автоматического статуса.
- Для ручного рассмотрения — от перехода в `manual_review` до решения сотрудника.
- Для регистрации заявки — от получения запроса на отправку до подтверждения регистрации.
- Для отображения решения — от сохранения решения до его появления в интерфейсе клиента.

Время ручного рассмотрения рассчитывается с учётом рабочего календаря банка.

**Ожидание дополнительной информации от клиента** (`need_info`) учитывается отдельно и не включается в активное время обработки банком.

## 4. Контроль соблюдения SLA

Для определения эффективности используются следующие метрики:

| Метрика | Формула |
|---|---|
| Соблюдение SLA | Заявки в срок / все завершённые заявки × 100% |
| Среднее время обработки | Сумма времени обработки / количество заявок |
| Доля нарушений SLA | Заявки с нарушением / все завершённые заявки × 100% |
| Доля ручного рассмотрения | Заявки на ручной проверке / все рассмотренные заявки × 100% |

**Предварительный целевой уровень соблюдения SLA — не менее 95%.**

Показатель является продуктовой гипотезой и требует проверки на фактических данных.

## 5. Обработка нарушений

Если установленный срок превышен, система должна:

1. Зафиксировать нарушение SLA.
2. Отметить просроченную заявку в кабинете сотрудника.
3. Сохранить длительность задержки.
4. Передать информацию ответственному сотруднику.
5. Использовать данные о нарушении при расчёте продуктовых метрик.

Для заявок, ожидающих информацию от клиента, необходимо отдельно учитывать время ожидания и время активной обработки.

## 6. Реализация в MVP

В backend проекта предусмотрено сохранение истории изменения статусов заявки с временными отметками.

Эти данные можно использовать как основу для расчёта длительности обработки.

Для полноценного контроля SLA необходимо дополнительно реализовать:

- Автоматический расчёт сроков и дедлайнов.
- Учёт рабочего времени сотрудников.
- Отдельный учёт ожидания действий клиента.
- Определение нарушений нормативов.
- Отображение показателей SLA в интерфейсе сотрудника.

Таким образом, **SLA определён на уровне требований**, а его автоматизированный контроль является задачей дальнейшего развития MVP.

## 7. Ожидаемый результат

Внедрение SLA позволит контролировать скорость обработки кредитных заявок, своевременно выявлять задержки и повышать эффективность работы сотрудников.

Основная цель — обеспечить быстрое рассмотрение стандартных заявок при сохранении качественной проверки нестандартных кредитных обращений.
